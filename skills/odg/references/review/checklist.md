# Review Checklist

> **MANDATORY:** Every item below **MUST** be fully evaluated and resolved. Skipped items **MUST NOT** occur.

- **Citation (MUST)** Every finding carries a verifiable citation: a repo `path:line`, a skill reference `path:line`, `node_modules/<pkg>/<file>:line` or checklist `Name:Line-Checklist`.
- **Forgiveness (MUST)** Legacy code around the change is out of scope unless the change caused the defect.

- [ ] **Correctness**
  - [ ] **Simplicity of the solution (MUST, ask first)** Before judging the implementation, judge the **approach**: given the problem the card describes, is there a materially simpler shape that solves it? A working, well-tested implementation of an unnecessarily complex approach is a **finding**, not an approval — state the simpler alternative concretely.
  - [ ] **Code with no consumer (MUST)** Every artifact the diff adds or keeps has a real consumer. Violations: an event dispatched with **no registered listener**; a public method whose only callers live in `tests/`; a feature partially implemented that the card never asked for; an exported symbol with zero references; a config key nothing reads; a parameter that never influences behavior. Framework infrastructure wired-but-unused (container, event bus, config, logger) is **not** a violation.
  - [ ] **Survivors of a change of direction (MUST)** **WHEN** the diff (or the conversation that produced it) changes an approach mid-task, every artifact built under the previous approach **MUST** be re-evaluated: implementation, tests, types, exceptions, enum entries, container wiring, aliases. Code that still compiles and passes tests but no longer earns anything under the new decision → violation. Sharpest signal: a bespoke algorithm (fuzzy match, parser, normalizer, scorer) deriving information the consumer already receives by another path.
  - [ ] **Defensive excess (MUST)** A guard, branch or handler for a condition that **cannot occur by construction** → violation. Includes: revalidating what the schema or type already guarantees; two or more branches that end in the **same** outcome (two `catch` blocks that both log and return empty are one); parsing an error body to refine a message; `try`/retry/cache/fallback around an operation the card never asked to make resilient. The error tracker already reports where and what — do not pay for that in code.
  - [ ] **Error boundary placement** The `try`/`catch` sits at the boundary of a **unit of work** (one card, one request, one message) — not one per operation. Inside that boundary, I/O and downstream calls throw freely. Violations: `try`/`catch` per operation **in order to continue** after a failure; a `catch` that logs and proceeds while hiding that the step did not happen; a rescue nested inside the failure handler instead of letting it reach the process-level handler. A `catch` **MUST** rethrow or log the original error object with context; discarding it or substituting a fallback/empty value is a violation unless the recovery is deliberate and commented inline. Distinct error semantics are still **REQUIRED** — do not collapse different failures into one generic status.
  - [ ] **WHEN** behavior moves between configs, tables, enums, seeds, validators, services, or schemas, the reviewer **MUST** search the old symbol, new symbol, persisted key, and domain term. Legacy artifacts **MUST** be removed or covered by a documented migration window.
- [ ] **Event wiring chain completeness** `EventName` enum updated, `@types/EventsInterface.d.ts` payload added, Listener exists and is registered (decorator path or provider path).
- [ ] **Base + specialization boundary** Shared artifacts (`*Base*`, `Common*`, `Core*`, or any class extended via subclass / `.extend(...)`) hold only fields and behavior used by **2+** specializations with equivalent semantics. A field in base consumed by only one specialization → violation, Specialization-specific fields and behavior stay in the specialized artifact. Applies to classes, interfaces, validators, configs, DTOs, schemas, constants, enums.
- [ ] **Unjustified abstraction (MUST)** Every indirection the diff *introduces* — helper file, exported function, wrapper method, extracted type, sub-schema, const map, service, fallback branch — **MUST** satisfy **at least one** of: (a) **2+ independent call sites inside the diff**; (b) it adds behavior beyond forwarding; (c) **its name states something the body does not** — see the naming exemption below. None of the three → violation. Decision procedure: *inline it at its single call site and reread the caller; is the caller worse?* If no → violation. Mechanical offenders: exported function whose body is a single `new X(...)`, `env.get(...)`, or one call + return; a file under `helpers/`/`util/` exporting one symbol used at one site; a method whose only caller is a sibling method of the same class, forwarding args only; an exported type/const/enum member with **zero** references outside its declaration; a `const` map or lookup table with exactly **one** entry; a fallback/retro-compatibility/bootstrap branch whose trigger the card does not name; a `try`/cache/memoization/retry around an operation the card does not ask to make resilient. An injected `Logger`, `Config`, requester, or `EventBus` wrapped in a function that only forwards to it → violation.
  - [ ] **Naming exemption (do NOT report)** A **single-call-site** extraction whose name replaces something the reader would otherwise have to decode **MUST NOT** be reported: a multi-clause condition named for its meaning (`canMoveCard(...)` instead of four chained `&&`), a named domain rule (`isWithinBusinessHours(...)`), or a block whose name lets the reader skip the body and still follow the flow. The name is the documentation, and that is behavior beyond forwarding. The inverse is still a violation: a name that merely restates the body (`getUserName(user) → user.name`) adds nothing.
  - [ ] **Fake helper (MUST)** A "helper" that extracts exactly the fields **one** caller needs, takes no parameter for the resource it operates on, and cannot be extended without being rewritten → violation. It is displacement, not abstraction: either it is born genuinely reusable (the resource arrives by parameter) or it goes inline at its caller.
- [ ] **External Validators Schema** Schemas consuming external or volatile payloads (third-party APIs, scraped responses, upstream service responses) **SHOULD** validate only the fields the consumer actually reads and **SHOULD** permit unknown fields via `.passthrough()` (or the equivalent escape in the schema library) so upstream additions do not break the parser, This rule applies regardless of the schema library (`zod`, `yup`, `io-ts`, etc.); detect the escape primitive native to the library in use.
- [ ] **Contract fidelity** For every changed public method or interface, parameters declared in the contract **MUST** influence behavior or output. A semantically relevant parameter ignored at the call site → violation. Trace `signature → implementation → downstream call payload`. A break in argument-flow integrity is a finding even when compilation passes.
- [ ] **Hidden state coupling** Logic that reads hidden state (injected payload snapshots, singleton mutable fields, ambient globals, process state) where an explicit method argument would suffice → violation, especially when reuse or concurrency can let the state diverge from the call arguments.
- [ ] **Layer ownership** Each concern stays in its layer: orchestration vs business rules, shared contract vs implementation detail, transport schema vs domain schema, base abstraction vs specialization. Cross-layer leak without explicit justification → violation.
- [ ] **Data declared as code (MUST)** Long text the program *carries* — prompts and agent instructions, message templates, static domain lists — **MUST** live in dedicated files, one per coherent unit, exported through the folder's barrel. Building it by concatenating fragments declared inside service methods → violation: the final text becomes unreadable without mentally executing the code. The consuming service **composes** named units; it does not author them. A parameterized unit whose entire body is one template literal is still data and is **correct**.
- [ ] **One reason to change per class (MUST)** Each class answers **one** question: how to talk to an external system, who owns a resource's lifecycle, how to run an engine, or in what order the process happens. An orchestrator that also performs I/O, compares state, or assembles payloads directly → violation; the operation belongs to the class owning the resource it touches, **even when only the orchestrator calls it**. Test: the orchestrator's main method should read as the sequence of the process.
- [ ] **Artifact placement (derive, don't inline)** Each folder owns one artifact kind — see `architecture.md` → *Universal spine*. A type derived from a validator **MUST** be `z.infer<typeof X>` and live in `Interfaces/`/`@types/`; a hand-written inline type duplicating the schema shape → violation. An artifact in the wrong folder (a type inside `Validator/`, an `enum` inside `Services/`, a schema inside `Interfaces/`) → violation. A status/union modeled as a static type where the project already derives it from `zod.enum(...)` → violation.
- [ ] **Illusory generic typing** — Explicit generic type arguments at the call site (e.g. fn<Req, Res>(...), parse<T>(...)) MUST NOT be used WHEN the returned value is not consumed (assigned, destructured, returned, or otherwise used). IF removing the generic causes no downstream type changes, it provides no real type safety and only creates a false sense of correctness. The generic MUST be removed, or the returned value MUST be captured and used.
- [ ] **Dependency hygiene** Development tooling declared under runtime `dependencies` in `package.json` → violation. Common offenders: `eslint`, `typescript`, `prettier`, `vitest`, `jest`, `tsc-alias`, `husky`, `concurrently`, `lint-staged`, `@types/*`, build orchestrators, *"does the deployed runtime import this at execution time?"* If no, it is `devDependencies`
- [ ] **Suppression revisit deadline** Any linter or type-checker suppression — `eslint-disable*`, `@ts-expect-error`, `@ts-ignore`, `@ts-nocheck`, `skipLibCheck`, or equivalent build-flag workaround — **MUST** carry `TODO [YYYY-MM-DD]: <upstream-condition>` **MUST NOT** Missing date, past date, vague reason, or symptom-only reason → violation.
- [ ] **Naming coherence** Patterns: legacy term inside a new abstraction namespace, specialization name mixed into an unrelated namespace, typo in a public symbol propagated to consumers, or two names for the same domain concept (e.g., `offer_id` vs `outbound_offer_id`) → maintainability violation **even when behavior is correct**.
- [ ] **Procedure for renames**: when `.review/$$GIT_BRANCH.md` shows a symbol rename — capture old + new verbatim, search both with the host's search primitive  across validators/interfaces/helpers/parsers/config keys; if both coexist with the same semantic meaning emit `competing contract keys`. Removal of the legacy symbol is **REQUIRED** unless it is explicitly kept for a documented migration window.
- [ ] **Duplicated literal/structural definitions (MUST)** When the **same** value, type, or composite expression appears **2+ times** within a single file scope or across files in the diff, it is a violation. The diagnostic question: *"if I add or remove one member here, do I have to edit N places to keep them in sync?"* — if yes, duplication. Applies (non-exhaustive) to: array/tuple literals, object shape literals, set/enum-member groupings, regex patterns, header/route dicts, retry/policy configs, type aliases, generic instantiations (`Foo<A, B, C>` repeated verbatim), discriminated-union variants, validator/schema compositions in **any** library. Exception: skip only when each occurrence is genuinely unrelated (same shape, different domain meaning) — and that fact **MUST** be explained inline at each site.
- [ ] **Type/Nullability Weakening Safety (MUST)**: If any configuration schema, class field, method parameter, or interface property is changed to be weaker (e.g., from required/non-nullable to `.nullish()`, `.optional()`, or nullable type), you **MUST** run `grep_search` across the entire codebase to trace all usages/call sites of this symbol and verify that consumers handle the null/undefined cases safely.
- [ ] **Cross-file trace pass (do last, MUST)** After per-file review, run **one** cross-file pass:
  - [ ] Identify changed shared/base artifacts, configuration keys, or interface fields.
  - [ ] Run `grep_search` on each changed symbol to find every dependent/specialized consumer file.
  - [ ] Verify boundary, flow, and type/nullability invariants across files. E.g., if a configuration value or property is changed to nullish or optional, verify that every consumer checks for null/undefined or has a safe fallback.
  - [ ] Emit one comment per violation, never collapse.
- [ ] **typo/misspelling** in symbol names (method, class, variable, enum member, file name)
- [ ] naming drift or inconsistent terms for the same domain concept
- [ ] **duplicate** enum/config sources-of-truth that increase ambiguity
- [ ] validator overfitting that tightly couples to volatile upstream payload fields
- [ ] **Library-first / No duplicate conventions** Do not hand-roll logic that standard libraries solve (e.g., database/Prisma, JWT, transport/@odg). Do not introduce competing packages (e.g., adding `yup` when `zod` is present) unless the value added outweighs the migration cost; otherwise, adhere to existing project packages.
- [ ] **Security hygiene**
  - [ ] **Untrusted input validation** Values crossing a trust boundary — HTTP/RPC responses, JWT claims, IPC payloads, query strings, env vars, file contents, websocket frames, scraped HTML — **MUST** be parsed through the project's schema library (`zod`, `yup`, `io-ts`) before any branching, coercion, persistence, or comparison. Truthy coercion (`Boolean(x)`, `!!x`, `if (x)`) on an unvalidated field is a violation: a producer returning `"false"`, `0`, `null`, or `{}` is coerced silently as "permitted". **WHEN** schema parsing is not feasible at the call site, strict-type comparison (`=== true`, `=== "value"`, `typeof x === "number"`) is **REQUIRED** at every read.
  - [ ] **Server is the source of truth** A value that carries authority — identity, permission, price/total, ownership, or any security- or business-critical state — **MUST** be derived from the trusted backend (verified token/session, persisted record, or server-side computation), **MUST NOT** be treated as authoritative when it comes from client/front-supplied input, even if that input is well-formed. Client input is a request, not the truth; trusting it to override existing data opens a tampering gap (e.g. privilege escalation, price/total manipulation).
  - [ ] Package hygiene and security Any newly added package **MUST** be secure, widely adopted, and actively supported. Introducing obscure, vulnerable, or inferior packages when better-established alternatives exist is a violation.
  - [ ] No SQL/NoSQL injection vulnerabilities
  - [ ] No XSS or CSRF vulnerabilities
  - [ ] No hardcoded secrets or sensitive credentials
  - [ ] AI-Specific: Protection against Prompt Injection (if applicable)
  - [ ] AI-Specific: Outputs are sanitized before being used in critical sinks
- [ ] **Performance optimization**
  - [ ] **Promise.all Independent** WHEN any action involves multiple asynchronous operations, ensure they are independent and can be executed concurrently using `Promise.all` or equivalent. Example: `const [user, posts, comments] = await Promise.all([fetchUser(), fetchPosts(), fetchComments()]);`
  - [ ] No N+1 complexity **WHEN** not need
  - [ ] No unnecessary loops
  - [ ] Appropriate caching if realtime is not required
  - [ ] Bundle size impact considered
- [ ] **Card Scope** Changes **MUST** be strictly within the scope of the assigned card or ticket. Unrelated refactoring or "drive-by" changes → violation.
- [ ] **Contextual Flow Bugs** The reviewer **MUST** actively trace the logic flow, searching for inverted conditions, missed edge cases, and incorrect states that static analysis cannot catch.
- [ ] **Naming vs Behavior** Method and variable names **MUST** accurately describe their behavior. For example, a method named `getUser` that also mutates the user → violation.
- [ ] **Optional vs Domain** Optional fields (`?`) **MUST** reflect true domain optionality. Using optional fields simply because data is temporarily missing in a specific flow → violation.
- [ ] **Cross-repo Standards** The reviewer **MUST** flag violations of cross-repo conventions or common library misuse, ensuring consistency across all consuming repositories.
- [ ] **Logger Promise Handling** Fire-and-forget promises (like `Logger.log`) **MUST** be handled safely. Use `Promise.allSettled` or a dedicated wrapper (e.g., `detach`) to prevent unhandled promise rejections. `await detach(promise, logger)` inside an `async` function is **correct** and **MUST NOT** be reported — see [conventions.md](../conventions.md).
